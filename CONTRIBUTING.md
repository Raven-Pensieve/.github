## 中文

感谢你对 Raven-Pensieve 项目感兴趣！我们非常欢迎来自社区的贡献，无论是报告 Bug、改进文档，还是提交代码。

本指南旨在帮助你更顺畅地参与到我们的项目中。

### 🤝 如何贡献

#### 1. 报告 Bug

如果你发现了 Bug，请在提交 Issue 之前：

1.  **搜索现有的 Issue**：查看是否已经有人报告过类似的问题。
2.  **提供详细信息**：如果没有现有 Issue，请创建一个新 Issue。请务必包含：
    *   清晰的标题。
    *   问题的详细描述。
    *   复现步骤（如果适用）。
    *   你的环境信息（如操作系统、软件版本等）。

#### 2. 建议新功能

如果你有新的想法或建议：

1.  在 Issue 中选择 "Feature Request"（如果有）或创建一个新 Issue。
2.  详细描述你的建议以及它能解决的问题。
3.  如果可能，提供模型图或示例。

#### 3. 提交代码

我们欢迎通过 Pull Request (PR) 提交的代码贡献。

1.  **Fork 仓库**：将项目 Fork 到你自己的 GitHub 账号。
2.  **Clone 仓库**：将 Fork 的代码克隆到本地。
3.  **创建分支**：在本地创建一个新的分支进行开发。建议分支命名具有描述性，例如 `feature/add-new-chart` 或 `fix/parsing-error`。
    ```bash
    git checkout -b feature/my-new-feature
    ```
4.  **进行开发**：
    *   遵循现有的代码风格和规范。
    *   确保添加或更新了相应的测试（如果项目包含测试）。
    *   确保代码能够通过构建和检查。
5.  **提交更改**：使用清晰且描述性的提交信息（Commit Message）。推荐遵循 [Conventional Commits](https://www.conventionalcommits.org/) 规范。
    ```bash
    git commit -m "feat: 添加了新的图表渲染组件"
    ```
6.  **推送分支**：将分支推送到你的 Fork 仓库。
    ```bash
    git push origin feature/my-new-feature
    ```
7.  **提交 Pull Request**：
    *   回到原始仓库，创建一个新的 Pull Request。
    *   填写 PR 模板（如果有），清晰地描述你的更改内容和目的。
    *   关联相关的 Issue（例如 `Closes #123`）。

### 📜 行为准则

为了维护一个开放、包容和健康的社区环境，所有参与者都必须遵守我们的 [行为准则 (Code of Conduct)](CODE_OF_CONDUCT.md)。

如果有任何违反行为准则的情况，请联系社区维护者。

### 📄 许可证

通过向本项目提交贡献，你同意你的贡献将根据该项目的相应许可证（通常是 MIT 或 GNU GPL）进行授权。

## English

Thank you for your interest in contributing to Raven-Pensieve projects! We welcome contributions from the community to help improve our projects, whether it's reporting bugs, improving documentation, or submitting code.

This guide is designed to help you participate in our projects more smoothly.

### 🤝 How to Contribute

#### 1. Reporting Bugs

If you find a bug, please check the following before submitting an issue:

1.  **Search existing Issues**: Check if someone has already reported a similar problem.
2.  **Provide detailed information**: If no existing issue is found, create a new one. Please includes:
    *   A clear title.
    *   A detailed description of the problem.
    *   Steps to reproduce (if applicable).
    *   Your environment information (e.g., OS, software version).

#### 2. Suggesting Enhancements

If you have new ideas or suggestions:

1.  Select "Feature Request" in Issues (if available) or create a new Issue.
2.  Describe your suggestion in detail and the problem it solves.
3.  Provide mockups or examples if possible.

#### 3. Pull Requests

We welcome code contributions via Pull Requests (PR).

1.  **Fork the Repository**: Fork the project to your own GitHub account.
2.  **Clone the Repository**: Clone your fork locally.
3.  **Create a Branch**: Create a new branch for your development. Descriptive branch names are recommended, e.g., `feature/add-new-chart` or `fix/parsing-error`.
    ```bash
    git checkout -b feature/my-new-feature
    ```
4.  **Develop**:
    *   Follow the existing code style and conventions.
    *   Ensure appropriate tests are added or updated (if the project includes tests).
    *   Ensure the code passes build and checks.
5.  **Commit Changes**: Use clear and descriptive commit messages. Following [Conventional Commits](https://www.conventionalcommits.org/) is recommended.
    ```bash
    git commit -m "feat: add new chart rendering component"
    ```
6.  **Push Branch**: Push the branch to your fork.
    ```bash
    git push origin feature/my-new-feature
    ```
7.  **Submit Pull Request**:
    *   Go back to the original repository and create a new Pull Request.
    *   Fill out the PR template (if available), clearly describing your changes and purpose.
    *   Link related Issues (e.g., `Closes #123`).

### 📜 Code of Conduct

To maintain an open, welcoming, and healthy community environment, all participants must adhere to our [Code of Conduct](CODE_OF_CONDUCT.md).

If there are any violations of the Code of Conduct, please contact the community maintainers.

### 📄 License

By contributing to this project, you agree that your contributions will be licensed under the project's respective license (usually MIT or GNU GPL).

Thank you for your support and contributions!
